# 2.1 - Common Ports 


## Main Idea

Port numbers identify specific network services running on a device.

For the CompTIA A+ exam, it is important to know:

-   The **port number**

-   The **protocol**

-   Whether it uses **TCP or UDP**

-   What the protocol is used for

Port numbers are especially useful when:

-   Troubleshooting network communication

-   Configuring firewalls

-   Allowing or blocking specific network traffic

A firewall can use TCP/UDP port numbers as criteria to determine whether network traffic should be allowed or blocked.

The goal is not only to memorize port numbers, but to understand what each protocol does and why it is used.

---

## Important Concepts

### 1\. FTP — File Transfer Protocol

**Ports:**

-   TCP **20** — Data transfer

-   TCP **21** — Control / administration

FTP is used to transfer files between devices.

FTP can:

-   Upload and download files

-   List files in directories

-   Add files

-   Delete files

-   Rename files

-   Perform other file-management operations

FTP may require authentication such as:

-   Username

-   Password

-   Other authentication factors

It can also support **anonymous access**, where users can connect without a normal personal account.

### FTP Port Roles

| Port | Protocol | Purpose |
| --- | --- | --- |
| 20 | TCP | FTP data transfer |
| 21 | TCP | FTP control / administration |

---

### 2\. SSH — Secure Shell

**Port:** TCP **22**

SSH provides secure, encrypted remote command-line access to another device.

It is commonly used by administrators to:

-   Remotely access servers

-   Configure network devices

-   Execute commands

-   Perform administrative tasks

SSH encrypts the communication between the client and the remote device.

#### Why SSH is important

Administrators may need to manage a remote system across an untrusted network.

Using SSH means the transmitted information is encrypted instead of being sent in plaintext.

**Key fact:**

> SSH = Secure remote command-line access = TCP 22

---

### 3\. Telnet

**Port:** TCP **23**

Telnet provides remote command-line access similar to SSH.

However, Telnet does **not provide encryption**.

This means usernames, passwords, commands, and other communication can be transmitted in cleartext.

Because of this, Telnet is generally avoided in modern environments.

It may still be encountered when dealing with:

-   Legacy systems

-   Very old network devices

-   Systems that do not support SSH

### SSH vs Telnet

| Feature | SSH | Telnet |
| --- | --- | --- |
| Port | TCP 22 | TCP 23 |
| Remote CLI | Yes | Yes |
| Encryption | Yes | No |
| Security | Secure | Insecure |
| Common today | Yes | Mostly legacy |

**Remember:**

**22 = SSH → Secure**
**23 = Telnet → No encryption**

---

### 4\. SMTP — Simple Mail Transfer Protocol

**Port:** TCP **25**

SMTP is used to **send email**.

Its primary purpose is transferring email:

-   From a mail client/device toward a mail server

-   From one mail server to another

SMTP is primarily associated with **sending/relaying email**, not retrieving it.

**Key fact:**

> SMTP = Send email = TCP 25

Email clients can also be configured with SMTP settings when sending messages through a mail server.

---

### 5\. DNS — Domain Name System

**Port:** UDP **53**

DNS translates domain names into IP addresses.

For example:

`www.professormesser.com`

can be translated into an IP address such as:

`162.159.246.164`

Humans generally prefer remembering domain names, while network communication uses IP addresses.

DNS performs this translation.

### Why DNS is important

Without DNS, users would frequently need to remember IP addresses instead of convenient domain names.

Organizations commonly use multiple DNS servers for **redundancy**, so name resolution can continue if one DNS server becomes unavailable.

**Key fact:**

> DNS = Domain name → IP address = UDP 53

---

### 6\. DHCP — Dynamic Host Configuration Protocol

**Ports:**

-   UDP **67**

-   UDP **68**

DHCP automatically provides network configuration information to devices.

A DHCP server can provide:

-   IP address

-   Subnet mask

-   Default gateway

-   DNS server information

This means a computer usually does not need to have all of this information manually configured.

### How DHCP Works

A simplified process:

1.  A device connects to the network.

2.  It requests network configuration.

3.  The DHCP server provides an available IP address and configuration parameters.

4.  The device uses the assigned IP address for a specific period of time.

5.  This period is called a **lease**.

6.  When the lease expires, the device can renew it or return the address to the available pool.

### DHCP Address Pool

A DHCP server maintains a pool of available IP addresses.

Example:

```text
192.168.1.100
192.168.1.101
192.168.1.102
192.168.1.103
...
```

When a device needs an address, DHCP can assign one from the available pool.

### DHCP Reservation

Administrators can reserve a specific IP address for a particular device.

For example, a printer can always receive:

`192.168.1.50`

This is useful for devices that should consistently have the same IP address, such as:

-   Printers

-   Servers

-   Other important network devices

### DHCP Ports

| Port | Protocol | Purpose |
| --- | --- | --- |
| 67 | UDP | DHCP server |
| 68 | UDP | DHCP client |

**Key fact:**

> DHCP = Automatic IP configuration = UDP 67/68

---

### 7\. HTTP — Hypertext Transfer Protocol

**Port:** TCP **80**

HTTP is used for web communication.

Standard HTTP sends data without encryption.

Therefore, HTTP traffic is considered **cleartext / unencrypted**.

**Key fact:**

> HTTP = Web traffic = TCP 80

---

### 8\. HTTPS — Hypertext Transfer Protocol Secure

**Port:** TCP **443**

HTTPS is the secure version of HTTP.

It provides encrypted web communication.

When you visit a website using HTTPS, the HTTP communication is protected through encryption.

Today, most websites use HTTPS rather than unencrypted HTTP.

### HTTP vs HTTPS

| Protocol | Port | Encryption |
| --- | --: | --- |
| HTTP | TCP 80 | No |
| HTTPS | TCP 443 | Yes |

**Remember:**

**80 = HTTP → Not encrypted**
**443 = HTTPS → Encrypted**

---

### 9\. POP3 — Post Office Protocol Version 3

**Port:** TCP **110**

POP3 is an email-receiving protocol.

It allows an email client to retrieve email messages from a mail server.

**Key fact:**

> POP3 = Receive email = TCP 110

---

### 10\. IMAP4 — Internet Message Access Protocol Version 4

**Port:** TCP **143**

IMAP is another protocol used for receiving and managing email.

Compared with POP3, IMAP provides more advanced mailbox management and synchronization features.

For example, you can:

-   Create folders

-   Move emails between folders

-   Manage your inbox

-   Keep mailbox changes synchronized between multiple email clients

This makes IMAP particularly useful when accessing the same mailbox from multiple devices.

### POP3 vs IMAP

| Feature | POP3 | IMAP |
| --- | --- | --- |
| Port | TCP 110 | TCP 143 |
| Receive email | Yes | Yes |
| Multi-device synchronization | Limited | Yes |
| Server-side mailbox management | Limited | Yes |

**Remember:**

**110 = POP3**
**143 = IMAP**

---

### 11\. SMB — Server Message Block

**Port:** TCP **445**

SMB is commonly associated with Microsoft Windows networks.

It is used for communication between Windows devices, including:

-   File sharing

-   File transfers

-   Printer sharing / printer queues

-   Other Windows network services

You may also see SMB associated with **CIFS (Common Internet File System)**.

### SMB and NetBIOS

Older Windows environments commonly used NetBIOS as part of Windows networking.

NetBIOS used:

-   UDP **137** — NetBIOS Name Service

-   TCP **139** — NetBIOS Session Service

Modern Windows systems can communicate directly using IP without requiring NetBIOS.

This is often called:

**Direct hosting / NetBIOS-less communication**

and commonly uses:

**TCP 445**

---

### 12\. NetBIOS

NetBIOS is associated primarily with older Windows networking.

#### UDP 137 — NetBIOS Name Service

Used for NetBIOS name resolution.

It is conceptually similar to what DNS does with domain names and IP addresses.

#### TCP 139 — NetBIOS Session Service

Used to establish sessions for communication such as file transfers.

### Important NetBIOS Ports

| Port | Protocol | Purpose |
| --- | --- | --- |
| 137 | UDP | NetBIOS Name Service |
| 139 | TCP | NetBIOS Session Service |

**Modern Windows:** TCP **445** is commonly used for SMB directly over IP without NetBIOS.

---

### 13\. LDAP — Lightweight Directory Access Protocol

**Port:** TCP **389**

LDAP is used to access information stored in directory services.

A directory can contain information about:

-   Users

-   Computers

-   Organizational units

-   Resources

-   Other network objects

LDAP can also be used to retrieve information about users and, in some environments, support authentication-related operations.

### Active Directory

A very common example of LDAP usage is **Microsoft Active Directory**.

LDAP allows applications and systems to query information stored in the directory.

For example, an organization might organize users into:

```text
Organization
│
├── Production
├── Support
└── Engineering
```

LDAP can be used to query information about these objects.

### LDAPS

**LDAPS** is the secure version of LDAP.

For the A+ exam, remember the relationship:

> LDAP → TCP 389

---

### 14\. RDP — Remote Desktop Protocol

**Port:** TCP **3389**

RDP allows remote access to a Windows computer.

It allows you to:

-   View a remote desktop

-   Control the remote computer

-   Run applications remotely

-   Troubleshoot systems without physically visiting them

RDP is primarily associated with Windows, but RDP client applications are available for many other operating systems, including:

-   macOS

-   Linux

-   Unix

-   iOS

This allows an administrator using one operating system to remotely control a Windows computer.

**Key fact:**

> RDP = Remote Windows desktop access = TCP 3389

| Port | Protocol | Service | Main Purpose |

| **68** | UDP | DHCP | DHCP client |

-   **FTP → 20/21**

-   **SSH → 22**

-   **Telnet → 23**

-   **SMTP → 25**

-   **DNS → 53**

-   **DHCP → 67/68**

-   **HTTP → 80**

-   **POP3 → 110**

-   **IMAP → 143**

-   **LDAP → 389**

-   **HTTPS → 443**

-   **SMB → 445**

-   **RDP → 3389**

### High-Value Relationships

**Remote administration**

-   SSH → 22 → Secure

-   Telnet → 23 → Not secure

-   RDP → 3389 → Remote desktop

**Email**

-   SMTP → 25 → Send

-   POP3 → 110 → Receive

-   IMAP → 143 → Receive/manage/synchronize

**Web**

-   HTTP → 80 → Unencrypted

-   HTTPS → 443 → Encrypted

**Network configuration/services**

-   DNS → 53 → Name resolution

-   DHCP → 67/68 → Automatic IP configuration

-   LDAP → 389 → Directory services

**Windows networking**

-   NetBIOS → 137/139

-   SMB → 445
