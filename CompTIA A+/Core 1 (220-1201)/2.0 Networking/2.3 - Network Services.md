# 2.3  - Network Services 


## Main Idea

A **network service** is a service or system that provides a specific function over a network.

In an enterprise/data center, you may have many different services running at the same time, including:

-   DNS

-   DHCP

-   File sharing

-   Print services

-   Email

-   Syslog / SIEM

-   Web servers

-   Authentication / AAA

-   Database servers

-   NTP

-   Spam gateways

-   Security appliances

-   Load balancers

-   Proxy servers

-   SCADA / ICS

-   Legacy systems

-   Embedded systems

-   IoT devices

The important idea is to understand **what each service does, why it is used, and how it fits into a network environment.**

# Important Concepts

## 1\. DNS — Domain Name System

**DNS** converts human-readable domain names into IP addresses.

For example:

```text
google.com
     ↓
DNS
     ↓
IP address
```

When you type a website such as `google.com` into your browser, your computer needs the website's IP address to communicate with it.

### What DNS does

-   Resolves a **Fully Qualified Domain Name (FQDN)** to an IP address.

-   Can also perform **reverse lookups**, converting an IP address back to a hostname.

-   Uses a distributed system of many DNS servers.

-   DNS information can also be **cached**, so your device may not need to contact the authoritative DNS server every time.

### Where DNS servers exist

DNS can be provided by:

-   Your Internet Service Provider (ISP)

-   A public DNS provider

-   Your organization's internal DNS servers

In an enterprise, multiple DNS servers may be used for **redundancy and availability**.

### Example

```text
You type:
www.example.com

DNS resolves it to:
192.0.2.10

Your computer then connects to:
192.0.2.10
```

# 2\. DHCP — Dynamic Host Configuration Protocol

**DHCP** automatically provides devices with IP configuration when they connect to a network.

Instead of manually configuring every computer, DHCP handles the configuration automatically.

### DHCP can provide

-   IP address

-   Subnet mask

-   Default gateway

-   DNS server information

-   Other network configuration

### Example

When you connect your laptop to Wi-Fi:

```text
Laptop
   ↓
DHCP request
   ↓
DHCP server
   ↓
IP configuration
```

Your laptop can then communicate on the network.

### Enterprise DHCP

Organizations often use **multiple DHCP servers** for redundancy.

If one DHCP server fails, another can continue providing configuration to clients.

# 3\. File Sharing

A **file-sharing service** allows users and systems to centrally store and access files over a network.

Examples:

-   Documents

-   Spreadsheets

-   Reports

-   Shared folders

-   Company files

Instead of keeping a file only on your computer:

```text
User 1 ─┐
User 2 ─┼──→ File Server
User 3 ─┘
```

Multiple users can access files from a central location, depending on their permissions.

### Common file-sharing protocols

#### SMB — Server Message Block

Commonly used in **Windows environments**.

#### AFP — Apple Filing Protocol

Used historically for **Apple/macOS environments**.

The operating system normally hides the underlying protocol. Users generally just see a normal file-management interface where they can:

-   Open

-   Copy

-   Move

-   Rename

-   Delete

-   Modify files

# 4\. Print Services

A **print service** manages network printing.

It handles:

1.  Receiving print jobs

2.  Queuing print jobs

3.  Sending jobs to the printer

4.  Managing multiple users' print requests

### Print server

The print service can run on:

-   A separate server/computer

-   The printer itself

-   A network interface/card built into the printer

Example:

```text
User 1 ─┐
User 2 ─┼──→ Print Server ──→ Printer
User 3 ─┘
```

### Common network printing protocols

-   **SMB** — Server Message Block

-   **IPP** — Internet Printing Protocol

-   **LPD** — Line Printer Daemon

# 5\. Email Servers

Email servers are responsible for sending and receiving email messages.

They may be:

-   Hosted in the cloud

-   Managed by an ISP/cloud provider

-   Located inside an organization's own data center

Email services usually have a **very high availability requirement**.

Users expect email to remain accessible and operational almost all the time.

Therefore, organizations may use:

-   Multiple email servers

-   Redundancy

-   High-availability systems

-   Backup systems

# 6\. Syslog and SIEM

Network devices such as:

-   Routers

-   Switches

-   Firewalls

-   Servers

generate **log files** containing information about events and activity.

Instead of keeping logs separately on every device, organizations can send them to a centralized system.

### Syslog

**Syslog** is commonly used to send/consolidate log information from network devices and systems.

```text
Router ──────┐
Switch ──────┤
Firewall ────┼──→ Central Logging / SIEM
Server ──────┤
             ┘
```

### SIEM

**SIEM** = **Security Information and Event Management**

> Important: The transcript says "Security Information and Event Manager," but the standard expansion of SIEM is **Security Information and Event Management**.

A SIEM acts as a central location for collecting and analyzing logs.

### Why use a SIEM?

A SIEM can:

-   Collect logs from many systems

-   Centralize security events

-   Correlate events from different systems

-   Help identify suspicious activity

-   Make security monitoring easier

Because a SIEM may receive huge amounts of logs, it generally requires significant storage capacity.

# 7\. Web Servers

A **web server** responds to requests from web browsers.

Common protocols:

-   **HTTP**

-   **HTTPS**

HTTP = **Hypertext Transfer Protocol**

HTTPS = **Hypertext Transfer Protocol Secure**

### How it works

```text
Browser
   ↓
HTTP / HTTPS request
   ↓
Web Server
   ↓
Web content
   ↓
Browser
```

Web pages are commonly created using **HTML — Hypertext Markup Language**.

The web server stores the web files, and the browser retrieves and interprets them to display the webpage.

# 8\. Authentication Server / AAA

An **authentication server** verifies a user's identity before allowing access to network resources.

For example:

```text
Username + Password
        ↓
Authentication Server
        ↓
Credentials verified
        ↓
Access granted
```

### AAA

You may hear authentication servers referred to as **AAA servers**.

**AAA** stands for:

-   **Authentication** — Who are you?

-   **Authorization** — What are you allowed to access?

-   **Accounting** — What did you do / what resources did you use?

### Enterprise authentication

Enterprise environments normally use centralized authentication so administrators can manage users from one location.

Each employee should have their **own credentials** rather than sharing an account.

### Redundancy

Authentication is often critical because it can be required before accessing many other resources.

Therefore, organizations may deploy multiple authentication servers so users can still authenticate if one server fails.

# 9\. Database Servers

A **database server** stores and manages structured information.

Database information is commonly organized into **tables**.

You can think of a table as being similar to a spreadsheet:

| ID | Name | Department |
| --- | --- | --- |
| 1 | Ahmed | IT |
| 2 | Sara | HR |
| 3 | Omar | Security |

A **relational database** can connect multiple tables through relationships.

For example:

```text
Employees Table
      ↓
Department ID
      ↓
Departments Table
```

This makes it possible to efficiently connect and retrieve related information.

### SQL

**SQL** = **Structured Query Language**

SQL is used to interact with many relational databases.

Examples include:

-   Microsoft SQL Server

-   MySQL

-   Other relational database systems

# 10\. NTP — Network Time Protocol

**NTP** is used to synchronize the date and time of networked systems.

Your computer periodically communicates with an NTP server to ensure its clock is accurate.

```text
NTP Server
     ↓
Correct time
     ↓
Computer / Server
```

### Why accurate time matters

Time synchronization is important for:

-   Comparing logs from different systems

-   Troubleshooting

-   Security monitoring

-   Authentication

-   Encryption technologies

-   Event correlation

If different systems have incorrect times, it becomes difficult to determine the actual order of events.

### NTP architecture

There may be one or more NTP servers referencing accurate time sources.

Client operating systems such as:

-   Windows

-   Linux

-   macOS

can run an **NTP client** that periodically synchronizes with an NTP server.

# 11\. Spam Gateway

A **spam gateway** filters incoming email and attempts to identify unwanted messages.

It may be:

-   Cloud-based

-   A separate server

-   Part of another security system

### Process

```text
Incoming Email
      ↓
Spam Gateway
      ↓
Evaluate message
      ↓
Legitimate? ──→ Inbox
      │
      └────────→ Spam/Junk
```

The gateway evaluates incoming messages and categorizes them.

### Important point

Spam filtering is **not 100% accurate**.

A legitimate email can sometimes be incorrectly classified as spam.

# 12\. Unified Security Appliance

Organizations may deploy an **all-in-one security appliance** at the edge of the network, between the internal network and the Internet.

You may hear terms such as:

-   **Next-Generation Firewall (NGFW)**

-   **Unified Threat Management (UTM)**

-   **Web Security Gateway**

Instead of having completely separate devices for every security function, one appliance can combine many functions.

### Possible functions

-   Firewall

-   Router

-   Switch

-   URL filtering

-   Content inspection

-   Malware detection

-   Spam filtering

-   IPS — Intrusion Prevention System

-   VPN

-   Bandwidth shaping

-   WAN connectivity

Some older WAN environments may also use a **CSU/DSU**.

### Bandwidth shaping

Bandwidth shaping can control how much network bandwidth certain applications or traffic types consume.

This helps prevent one application from negatively affecting the entire network.

# 13\. Load Balancer

A **load balancer** distributes incoming network requests across multiple servers.

For example, an organization may have several web servers:

```text
             ┌──→ Web Server 1
             │
Users → Load Balancer ──→ Web Server 2
             │
             └──→ Web Server 3
```

Instead of sending every request to one server, the load balancer distributes requests across the available servers.

### Why use a load balancer?

-   Improve performance

-   Distribute workload

-   Increase availability

-   Provide redundancy

-   Reduce the impact of server failures

### If one server fails

Suppose:

```text
Server 1 → Online
Server 2 → Failed
Server 3 → Online
```

The load balancer detects that Server 2 is unavailable and removes it from the active rotation.

Traffic continues to:

```text
Server 1
Server 3
```

When Server 2 is repaired and becomes available again, the load balancer can automatically add it back.

### Key concept

The end user may not even notice that a server failed.

# 14\. Proxy Server

A **proxy server** acts as an intermediary between a client and another service.

Instead of:

```text
Client → Internet Server
```

the communication becomes:

```text
Client → Proxy → Internet Server
```

The proxy makes the request on behalf of the client.

### Basic process

1.  Client sends a request to the proxy.

2.  Proxy sends the request to the destination.

3.  Destination sends a response to the proxy.

4.  Proxy evaluates the response.

5.  Proxy sends the response to the client.

### Why use a proxy?

A proxy can provide:

-   Security

-   Access control

-   Content filtering

-   Content inspection

-   Caching

For example, an organization can use a proxy to prevent users from accessing certain websites or content.

### Transparent operation

A proxy can operate in a way that is largely invisible to users.

Users may not even realize that their traffic is passing through a proxy.

# 15\. SCADA / ICS

Organizations that operate large-scale industrial systems may use **SCADA** or **ICS**.

### SCADA

**SCADA** = **Supervisory Control and Data Acquisition**

### ICS

**ICS** = **Industrial Control System**

These systems are commonly associated with environments such as:

-   Power generation/distribution

-   Oil and gas

-   Manufacturing

-   Industrial facilities

SCADA allows organizations to:

-   Monitor industrial equipment

-   View system status

-   Control equipment

-   Manage systems remotely

-   Collect operational information

### Security is extremely important

SCADA/ICS systems can control physical infrastructure.

A compromise could therefore have serious real-world consequences.

For this reason, organizations often use **segmented networks** for these systems.

Access may be limited to:

-   Physical access

-   Highly controlled network connections

-   Dedicated management systems

### Cybersecurity relevance

This is particularly important in **cybersecurity and OT (Operational Technology)** because attacking an IT system may compromise data, while attacking an industrial control system can potentially affect **physical processes and infrastructure**.

# 16\. Legacy Systems

A **legacy system** is an older system or technology that is still being used.

A system might be:

-   10 years old

-   15 years old

-   20+ years old

and still be critical to an organization.

### Important point

**Old does not mean unimportant.**

Organizations may keep legacy systems because:

-   They still perform an important function.

-   Replacing them is expensive.

-   Replacement may require major downtime.

-   Modern systems may not support the old application.

-   The organization depends heavily on the system.

Therefore, IT professionals may need to know how to maintain and secure old technologies.

---

# 17\. Embedded Systems

An **embedded system** is a purpose-built computing system designed to perform a specific function.

Unlike a normal PC, you usually don't have direct access to the underlying operating system.

### Examples

-   Fire alarm systems

-   Time clock systems

-   Specialized control systems

-   Appliances

-   Industrial equipment

You interact with the device through the interface provided by the manufacturer.

For example:

```text
User
 ↓
Device Interface
 ↓
Embedded System
 ↓
Hidden OS / Firmware
```

The manufacturer normally provides the tools required to configure and maintain the system.

Embedded systems often require relatively little direct maintenance from the end user.

---

# 18\. IoT — Internet of Things

**IoT** = **Internet of Things**

IoT is a broad category of devices that connect to a network or the Internet.

### Examples

-   Smart refrigerators

-   Smart coffee makers

-   Smart thermostats

-   Smart speakers

-   Smart doorbells

-   Smart garage doors

-   Heating and air-conditioning controls

These devices can often be remotely monitored or controlled.

### Security concern

One major IoT security problem is that the manufacturer may be excellent at building the physical product but not necessarily excellent at:

-   Network security

-   Secure software development

-   Vulnerability management

-   Long-term security updates

For example, a company may be very good at manufacturing a refrigerator but not have the same level of expertise as a cybersecurity company.

### IoT network segmentation

A common security approach is to put IoT devices on a **separate segmented network**.

```text
Corporate Network
       │
       ├── PCs
       ├── Servers
       └── Critical Systems

IoT Network
       │
       ├── Smart Cameras
       ├── Smart Thermostats
       └── Smart Devices
```

If an IoT device becomes compromised, segmentation can limit the attacker's ability to move into the main corporate network.

# Detailed Explanation

## How These Services Work Together

A real enterprise network can contain many of these services simultaneously.

Imagine an employee connecting a laptop:

```text
                    ┌── DNS
                    │
Laptop → Network ───┼── DHCP
                    │
                    ├── Authentication
                    │
                    ├── File Server
                    │
                    ├── Web Server
                    │
                    ├── Email
                    │
                    └── NTP
```

The user may never directly see these services, but they are working behind the scenes.

### Example: Opening a company website

```text
Laptop
  ↓
DHCP
  ↓
Gets IP configuration
  ↓
DNS
  ↓
Resolves website name
  ↓
Proxy / Firewall
  ↓
Load Balancer
  ↓
Web Server
  ↓
Website
```

This is why understanding individual network services is important: **they work together to provide the overall network experience.**

# High-Availability Concepts

Several services in this video emphasize **availability and redundancy**.

### DNS

Multiple servers can provide DNS services.

### DHCP

Multiple DHCP servers can provide redundancy.

### Email

Email infrastructure is designed for very high uptime.

### Authentication

Multiple authentication servers can prevent authentication from becoming a single point of failure.

### Load Balancing

Multiple servers share the workload, and failed servers can be removed from the rotation.

The general idea is:

> **Don't allow one failed component to bring down an important service.**
